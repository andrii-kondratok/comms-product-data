# Звідки брати тексти статей

Для розмови з Тимофієм. Усі цифри — вимір на наших власних статтях, 13–14.09.2026.

---

## Коротка відповідь

**API не покриває нашу задачу — не тому, що гірше, а тому, що потрібних джерел у ньому немає.**

| Варіант | Статей із потоку 2 868 | Покриття |
|---|---|---|
| Тільки API | 938 | **33%** |
| Тільки власний витяг | 1 605 | **56%** |
| Обидва разом | 1 851 | **65%** |
| Не покриває ніхто | 1 017 | 35% |

Архітектура тільки на API втратила б **913 статей за 5.4 місяця** (~170/міс) — майже третину потоку.

## Що саме перевірено

Три провайдери, 24 наші реальні статті, потім окремо по одній статті на кожне з 21 закордонного видання зі списку Digest Layout.

Список цих 24 статей — на початку `provider-letters.md`.

| | Perigon | NewsCatcher | NewsAPI.ai |
|---|---|---|---|
| Знайшов із 24 | 12 | 17 | 12 |
| **Віддав повне тіло** | **0** | **0** | **6** |
| Типова відповідь | 218 знаків | 303 знаки | повне або 300 |

Perigon і NewsCatcher повертають снипет незалежно від статті. У Perigon це видно з їхнього ж поля: `enContentWordCount` каже 1 094 слова, а `content` містить 218 знаків. Для Telegraph у них 0 слів, для The Times — 7.

NewsAPI.ai — єдиний, хто справді віддає текст: Foreign Affairs 13 281 знак, 98% від нашої версії.

---

## Три факти, які вирішують

**1. Наше джерело №1 не індексує ніхто.**
`united24media.com` — 385 статей за період, найбільше джерело дайджесту, більше за Reuters. Немає ні в Perigon, ні в NewsAPI.ai; є лише в NewsCatcher, і то снипетом на 303 знаки. Власним витягом береться на 104%.

**2. Провайдери самі не мають текстів платних видань.**
NewsAPI.ai підтвердив письмово: *«NYT, FT, The Times, Economist мають суворі ліцензійні обмеження, які не дозволяють повністю індексувати їхній контент»*, і що **це не залежить від тарифу**. Апгрейд не змінює нічого — купити нема чого.

**3. Головна перешкода технічна, а не ліцензійна.**
З 1 263 недоступних статей **1 125 — це антибот**, а не пейвол: сервер повертає 401 або таймаут, хоча текст на сторінці є і людина його бачить. Справжній пейвол лише в The Times і SCMP — 138 статей.

## Де API справді потрібен

Два домени, і обидва — антибот: **Reuters (180) і CNN (66)**. Разом 246 за період, ~46/міс, 9% потоку. NewsAPI.ai віддає Reuters повним текстом.

Тобто API не замінює витяг, а **закриває його сліпу пляму**. І навпаки.

---

## Пропозиція: не або-або, а каскад

```
1. API провайдера        ← якщо джерело покрите і ліцензія дозволяє
2. Власний витяг         ← якщо API не має цього джерела
3. Ручне копіювання      ← як зараз, для решти
```

Кожна стаття зберігає, **яким способом отримана** (`retrieval_method`) і з яким результатом. Спосіб задається **на рівні джерела в реєстрі**, а не в коді.

Це дає рівно те, чого хоче Тимофій, без втрати покриття:

- коли провайдер додає джерело — міняємо один рядок у реєстрі, код не чіпаємо;
- частка статей, отриманих через API, стає **вимірюваною метрикою**, яку видно на дашборді й яка може зростати;
- якщо якийсь витяг ламається — видно одразу, по конкретному джерелу, а не «щось не працює».

## Що в запереченні Тимофія правильне

Варто визнати прямо, бо це впливає на дизайн:

- **Парсер ламається** при зміні верстки. Ми вже спіймали таке: `zona.media` віддав 71 тис. знаків замість 6 тис., бо зачепив навігацію. Тому в екстракторі є верхня межа правдоподібності, і аномалії позначаються, а не тихо потрапляють у корпус.
- **ToS-ризик.** Те, що сторінка відкрита, не означає дозволу на автоматичний збір і тим паче на тренування моделі. Для внутрішнього дайджесту ризик малий, для платного продукту — ні.
- **Підтримка.** 49 доменів із власним витягом треба періодично перевіряти. У нас для цього є скрипт, який проганяє всі джерела й показує, де впало.

Жодне з цього не вирішується переходом на API — бо API з потрібними джерелами не існує. Але все це варто закласти в дизайн, і закладено.

---

## Рішення, яке пропонується

1. Будуємо каскад із трьох способів, спосіб задається в реєстрі джерел.
2. Для Reuters і CNN беремо API — там він виграє.
3. Для решти 49 доменів — власний витяг, із контролем якості й моніторингом.
4. Для 1 017 статей, які не бере ніхто, лишається ручна робота редакції, як і зараз.
5. Юридичне питання про тренування на чужих текстах виносимо окремо — воно однакове для обох способів.
